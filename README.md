# News Grid

News Grid — небольшое новостное приложение, в котором одну и ту же реальную новость можно прочитать с разной эмоциональной подачей. Фактическая основа остаётся прежней, а меняются лексика, ритм и интонация текста.

Сейчас доступны три AI-режима:

- позитивный;
- грустный;
- ироничный.

Оригинал всегда остаётся доступен. На странице материала он показан рядом с выбранной AI-версией, поэтому результат можно проверить без переходов между экранами. Под каждой новостью также есть ссылка на первоисточник.

## Что реализовано

- загрузка реальных новостей из публичного RSS Lenta.ru;
- извлечение полного текста с оригинальной страницы;
- сохранение источника, URL, автора, категории, изображения и дат публикации;
- защита от повторного импорта одной и той же новости;
- генерация трёх эмоциональных версий через OpenAI-совместимый API;
- отдельная автоматическая проверка фактов и соответствия выбранному тону;
- повторное исправление версии, которую отклонил фактчекер;
- хранение оригиналов, рерайтов и результатов проверки в базе данных;
- очередь для долгих AI-запросов;
- почасовой импорт через Laravel Scheduler;
- адаптивная новостная сетка и отдельная страница сравнения;
- ссылка на оригинальную публикацию для каждого материала;
- автоматические тесты без реальных запросов к Lenta.ru и AI-провайдеру.

## Как это работает

```text
RSS Lenta.ru
    ↓
загрузка метаданных и полного текста статьи
    ↓
таблица news
    ↓
очередь генерации трёх эмоциональных версий
    ↓
AI-фактчек каждой версии
    ↓
исправление отклонённых версий и повторная проверка
    ↓
таблица news_rewrites
    ↓
показ только успешно проверенных рерайтов
```

Команда `news:fetch` берёт свежую RSS-ленту и сохраняет до 10 новых статей за один запуск. После сохранения каждая статья автоматически отправляется в очередь на генерацию рерайтов. Уже импортированные публикации определяются по паре `source_name + external_id` и повторно не загружаются.

Генерация и проверка вынесены из HTTP-запроса в фоновые jobs. Поэтому страница остаётся доступной, пока AI обрабатывает материалы, а временные сетевые ошибки не блокируют импорт новостей.

## Откуда берутся новости

Источник — публичная RSS-лента новостей Lenta.ru:

```text
https://lenta.ru/rss/news
```

RSS содержит заголовок, ссылку, дату, автора, категорию и изображение. Полный текст извлекается с оригинальной страницы Lenta.ru. В базу сохраняется именно полученный текст, а не тестовая или заранее подготовленная новость.

Парсер принимает только HTTPS-ссылки с домена `lenta.ru`. Это не позволяет случайно отправить загрузчик на произвольный адрес. Если разметка статьи изменилась или текст извлечь не удалось, такая публикация пропускается, причина записывается в лог, а импорт остальных новостей продолжается.

## Как хранится информация

Для локальной разработки по умолчанию используется SQLite. Docker Compose запускает PostgreSQL с постоянным volume.

### `news`

Таблица хранит исходную публикацию:

- внешний идентификатор и название источника;
- оригинальный URL;
- автора и категорию;
- исходные заголовок, лид и полный текст;
- URL изображения;
- дату публикации и время загрузки.

Комбинация источника и внешнего идентификатора уникальна, поэтому повторный запуск импорта не создаёт дубликаты.

### `news_rewrites`

Для каждой новости может существовать одна версия каждого настроения. В записи хранятся:

- настроение: `positive`, `sad` или `ironic`;
- состояние обработки: `pending`, `processing`, `completed` или `failed`;
- переписанные заголовок, лид и полный текст;
- результат фактчека;
- понятное сообщение проверки или технической ошибки.

На уровне базы действует уникальность пары `news_id + mood`. При удалении оригинальной новости связанные рерайты удаляются каскадно.

## Как меняется тон

Приложение не содержит вручную написанных эмоциональных версий. Все рерайты создаются во время работы приложения через настроенный OpenAI-совместимый endpoint.

Модель получает исходный заголовок, лид и полный текст, а также отдельные инструкции для каждого режима:

- **позитивный** — более светлая и оптимистичная редакционная интонация без выдуманных достижений и положительных последствий;
- **грустный** — сдержанная печальная подача без выдуманных жертв, переживаний и трагических обстоятельств;
- **ироничный** — лёгкая ирония только в редакторских формулировках, без вымышленных действий, мыслей и цитат участников.

Один структурированный запрос создаёт три независимые версии. Ответ принимается только в заданной JSON-схеме с полями `title`, `lead` и `content`. Это позволяет отделить текст от служебного ответа модели и отклонить некорректный формат до сохранения результата.

## Как контролируется сохранение фактов

Контроль сделан в несколько этапов.

1. **Жёсткие правила генерации.** Модель получает инструкцию не менять имена, организации, должности, даты, числа, суммы, места, цитаты, источники утверждений, причинно-следственные связи и степень уверенности. Внешние знания использовать запрещено.
2. **Локальные предупреждения.** Перед фактчеком приложение ищет числа, которых не было в оригинале, и полностью совпадающие версии разных настроений. Эти сигналы передаются проверяющей модели.
3. **Отдельный AI-фактчек.** Каждый рерайт сравнивается с оригиналом по четырём группам ошибок: противоречия, добавленные утверждения, потерянные существенные факты и изменения цитат. Одновременно проверяется соответствие выбранному тону.
4. **Автоматическое исправление.** Если версия не прошла проверку, модель получает оригинал, отклонённый текст и конкретное описание ошибок. После исправления текст проверяется снова. Для одного настроения допускается до двух попыток исправления.
5. **Фильтрация на сервере.** Интерфейс получает только версии со статусом `completed` и положительным результатом проверки. Непроверенный или отклонённый текст читателю не показывается.
6. **Прозрачное сравнение.** Оригинал и рерайт расположены рядом, а ссылка на первоисточник доступна непосредственно на странице статьи.

Автоматическая проверка уменьшает риск и не позволяет публиковать рерайт, который сама система признала некорректным. При этом AI-фактчек не является математической гарантией и не заменяет редактора в реальном медиа: генерацию и проверку выполняет настроенная языковая модель, а локальная проверка чисел носит вспомогательный характер.

## Быстрый запуск через Docker

Понадобятся Docker Compose и доступный AI-endpoint. Самый простой бесплатный вариант — запустить модель локально через LM Studio.

### 1. Подготовьте окружение

```bash
cp .env.example .env
```

Docker Compose требует непустой `APP_KEY`. Получите 32 случайных байта:

```bash
openssl rand -base64 32
```

Добавьте полученное значение в `.env` с префиксом `base64:`:

```dotenv
APP_KEY=base64:сюда_вставьте_сгенерированное_значение
```

### 2. Настройте AI

Для LM Studio, запущенного на компьютере на стандартном порту, Docker-конфигурация уже использует адрес хоста:

```dotenv
AI_PROVIDER=lmstudio
AI_API_KEY=
OPENAI_MODEL=идентификатор_загруженной_модели
OPENAI_URL=http://host.docker.internal:1234/v1/chat/completions
```

Модель должна поддерживать structured output в формате JSON Schema. Перед запуском приложения загрузите модель в LM Studio и включите локальный API-сервер.

Для OpenRouter используйте:

```dotenv
AI_PROVIDER=openrouter
AI_API_KEY=ваш_ключ
OPENAI_MODEL=идентификатор_модели
OPENAI_URL=https://openrouter.ai/api/v1/chat/completions
```

Выбранная модель также должна поддерживать передаваемую JSON Schema.

### 3. Запустите контейнеры

```bash
docker compose up --build -d
```

Контейнер приложения сам применит миграции. Отдельный контейнер `worker` начнёт обрабатывать очередь.

### 4. Загрузите новости

```bash
docker compose exec app php artisan news:fetch
```

Команда сохранит до 10 новых материалов и сразу поставит их в очередь на генерацию. За обработкой можно наблюдать так:

```bash
docker compose logs -f worker
```

После запуска приложение доступно по адресу:

```text
http://localhost:8000
```

После изменений PHP или frontend-кода Docker-образ нужно пересобрать:

```bash
docker compose up --build -d
```

## Локальный запуск без Docker

Понадобятся PHP 8.4 с SQLite, Composer 2, Node.js и npm.

```bash
cp .env.example .env
touch database/database.sqlite
composer run setup
```

`composer run setup` установит PHP- и JavaScript-зависимости, создаст `APP_KEY`, применит миграции и соберёт frontend.

Если LM Studio работает на том же компьютере, замените Docker-адрес в `.env`:

```dotenv
OPENAI_URL=http://127.0.0.1:1234/v1/chat/completions
```

Запустите сервер, queue listener, логи и Vite одной командой:

```bash
composer run dev
```

В отдельном терминале загрузите новости:

```bash
php artisan news:fetch
```

## Автоматическое обновление новостей

В приложении уже зарегистрирован почасовой импорт:

```php
Schedule::command('news:fetch')->hourly()->withoutOverlapping();
```

Интервал задаётся в `routes/console.php`. Например, `everyThirtyMinutes()` запустит импорт каждые 30 минут, а `everyTwoHours()` — каждые два часа.

Важно: queue worker и scheduler выполняют разные задачи. Worker обрабатывает уже поставленные в очередь AI-рерайты, но сам по расписанию новые новости не загружает. Для автоматического обновления должен постоянно работать Laravel Scheduler.

При локальном запуске его можно запустить в отдельном терминале:

```bash
php artisan schedule:work
```

При запуске через текущий Docker Compose команда выглядит так:

```bash
docker compose exec app php artisan schedule:work
```

Обе команды работают в foreground и должны оставаться запущенными. Для постоянного Docker-развёртывания следует добавить отдельный scheduler-контейнер с командой `php artisan schedule:work` и политикой перезапуска.

На обычном Linux-сервере вместо долгоживущего процесса достаточно одной cron-записи, которая каждую минуту передаёт управление Laravel:

```cron
* * * * * cd /path/to/news-grid && php artisan schedule:run >> /dev/null 2>&1
```

Сам импорт при этом выполнится с интервалом, указанным в `routes/console.php`. Без `schedule:work`, cron или отдельного scheduler-контейнера новости обновляются только после ручного запуска `news:fetch`.

## Полезные команды

Загрузить до 10 новых новостей и автоматически поставить их на рерайт:

```bash
php artisan news:fetch
```

Повторно поставить в очередь одну новость:

```bash
php artisan news:rewrite 12
```

Поставить в очередь несколько последних новостей:

```bash
php artisan news:rewrite --latest=10
```

Принудительно пересоздать даже успешно завершённые версии:

```bash
php artisan news:rewrite 12 --force
```

Удалить все новости, рерайты и ожидающие jobs:

```bash
php artisan news:clear
```

Команда удаления запросит подтверждение. Флаг `--force` отключает вопрос и предназначен только для осознанного сброса тестовых данных.

## Что происходит при ошибках

- Временные сетевые и серверные ошибки AI-запроса повторяются автоматически.
- Queue jobs имеют три попытки с увеличивающейся задержкой.
- Ошибка отдельной статьи Lenta.ru не останавливает импорт остальных материалов.
- Если фактчекер отклонил текст, переписывается только проблемный тон, после чего он проверяется заново.
- Если версия остаётся некорректной после двух исправлений, она получает статус `failed` и не показывается пользователю.
- Ошибка самого запроса фактчека не считается доказательством плохого текста: очередь сначала повторяет проверку уже созданной версии.
- Исчерпание дневного лимита бесплатной модели помечается как невосстановимая ошибка текущего запуска. После восстановления лимита материал можно снова поставить в очередь командой `news:rewrite`.

Посмотреть упавшие jobs:

```bash
php artisan queue:failed
```

При запуске через Docker добавляйте к Artisan-командам префикс:

```bash
docker compose exec app php artisan ...
```

## Тесты и проверки качества

HTTP-запросы к RSS, страницам Lenta.ru и AI-провайдеру в тестах подменяются через Laravel HTTP fake. Тестовый набор проверяет импорт, дедупликацию, извлечение текста, модели, команды, очередь, structured output, повторные попытки, фактчек, исправление отклонённого тона и Inertia-страницы.

Запуск тестов:

```bash
php artisan test --compact
```

Остальные проверки:

```bash
npm run lint:check
npm run format:check
npm run types:check
vendor/bin/phpstan analyse --memory-limit=512M
npm run build
```

## Использование AI при разработке

В работающем приложении AI используется только для создания эмоциональных версий и их автоматической проверки. Провайдер и модель не зашиты в код и выбираются через `.env`; можно использовать локальную модель через LM Studio или совместимую модель через OpenRouter.

OpenAI Codex использовался как помощник при работе над кодом, тестами и этой документацией. Он не создавал набор заранее подготовленных новостей или рерайтов для демонстрации: данные загружаются с Lenta.ru, а эмоциональные версии генерируются приложением после импорта.

## Ограничения

- Парсер полного текста зависит от текущей HTML-разметки Lenta.ru.
- Качество стилизации и фактчека зависит от выбранной модели.
- Для реального редакционного использования потребовалась бы дополнительная человеческая проверка, особенно для чувствительных тем.
- Приложение использует один новостной источник, поскольку задача требует минимум 10 реальных публикаций, а не полноценный агрегатор.
